# Назначение и смена администратора

[README](../README.md) · [Команды Docker Compose](deployment.md)

Инструкция для технического специалиста. Администратор управляет доступом к учёту опозданий через `/admin`/`admin`. Получатели служебных уведомлений настраиваются отдельно и могут быть другими людьми.

## Назначить главного администратора в Telegram и VK

1. Попросите пользователя зарегистрироваться в обоих ботах.
2. Узнайте его числовые ID в таблице users соответствующего бота: Telegram ID — поле telegram_id, VK ID — поле vk_id. Это не @username и не ID бота.
3. Telegram: на TG-сервере добавьте Telegram ID в список admins в .env, сохранив остальных администраторов. Например: admins=[123456789, 987654321]. Примените настройки через Docker Compose.
4. VK: технический специалист разовым Python-скриптом в контейнере ВК-бота находит пользователя по vk_id и добавляет его внутренний users.id в таблицу admins. Перезапуск не нужен.
5. Только на TG-сервере примените изменения `.env` из каталога проекта:

```bash
docker compose up -d --no-build school-routine-bot
```

Попросите нового администратора отправить `/admin` в ТГ-версии и/или `admin` в ВК-версии и проверить, что меню открылось. Это скрытая команда доступная только главным администраторам.

## Заменить главного администратора или отозвать доступ

Сначала назначьте нового администратора и проверьте его доступ. Затем удалите ID прежнего из `admins` в `.env` и примените настройки командой выше.

**Этого недостаточно для отзыва прав:** уже выданная роль сохраняется в базе. Технический специалист должен также удалить роль прежнего администратора из таблицы `admins`, сохранив запись пользователя в `users`. Команды отзыва этой роли в боте нет.

## Особенность ВКонтакте

В текущем развёртывании базы TG и VK раздельные. Список `admins` в `.env` обрабатывается по Telegram ID даже в VK-версии. Для пользователя только ВК назначение и отзыв прав выполняет разработчик в базе ВК; регистрация или смена прав на TG-сервере их не переносит.

## Сменить получателя служебных уведомлений (администраторы второго порядка - отвественные за пустые слоты и новых для тг-версии юзеров)

В `school_routine_bot/admin_base_1.json` замените запись нужного получателя, сохранив остальных:

```json
[{"admin_id": 123456789, "name": "Иван", "by_father_name": "Иванович"}]
```

Укажите ID в соответствующем мессенджере и попросите получателя разрешить сообщения бота. Для теста без получателей используйте `[]`. В демо файл подключается к контейнеру с хоста; после изменения перезапустите сервис:

```bash
docker compose restart school-routine-bot
```

Это администраторы другого назначения - люди,в 13.00 получающие в ТГ-версии инфо о пустых слотах и о том, кто не является пользователем ТГ-бота. При передаче обязанностей проверьте и права администратора, и список получателей. Этот список не выдаёт права на команды `/admin` в ТГ / `admin` в ВК. Скрытая админская команда доступна только главному админу/админам и позволяет управлять списком дежурных по опозданиям.
