# Назначение и смена администратора

Русский | [English](en/admin_management.md)

[README](../README.md) · [Команды Docker Compose](deployment.md)

Инструкция для технического специалиста. Администратор управляет доступом к учёту опозданий через `/admin`/`admin`. Получатели служебных уведомлений настраиваются отдельно и могут быть другими людьми.

## Назначить главного администратора в Telegram и VK

1. Попросите пользователя зарегистрироваться в обоих ботах.
2. Узнайте его числовые ID в таблице users соответствующего бота: Telegram ID — поле telegram_id, VK ID — поле vk_id. Это не @username и не ID бота.
3. Telegram: на TG-сервере добавьте числовой Telegram ID пользователя в список admins в .env, сохранив остальных администраторов. Примените настройки через Docker Compose.
4. VK: технический специалист разовым Python-скриптом в контейнере ВК-бота находит пользователя по vk_id и добавляет его внутренний users.id в таблицу admins. Перезапуск не нужен.
5. Только на TG-сервере примените изменения `.env` из каталога проекта:

```bash
docker compose up -d --no-build school-routine-bot
```

Попросите нового администратора отправить `/admin` в ТГ-версии и/или `admin` в ВК-версии и проверить, что меню открылось. Это скрытая команда доступная только главным администраторам.

## Заменить главного администратора или отозвать доступ

Роль главного администратора хранится в таблице `admins`: её `id` — это внутренний `users.id`, а не Telegram ID или VK ID. Команды отзыва этой роли в боте нет. Скрипт ниже снимает роль, сохраняя запись пользователя в `users`.

1. Если это замена администратора, сначала назначьте нового и проверьте его доступ.
2. Удалите Telegram ID прежнего администратора из `admins` в `.env`, сохранив остальные ID. Если список пуст, явно укажите `admins=[]`: при полном удалении настройки подставится список из `settings.py`. Для пользователя только ВК этот шаг не требуется.
3. Если меняли `.env`, примените настройки из каталога проекта:

```bash
docker compose up -d --no-build school-routine-bot
```

4. На сервере соответствующего бота выполните следующий скрипт из каталога проекта. Замените `<ID_ПОЛЬЗОВАТЕЛЯ>` внутри кавычек на числовой ID пользователя в нужном мессенджере: Telegram ID на TG-сервере или VK ID на VK-сервере.

```bash
docker compose exec -T school-routine-bot .venv/bin/python - <<'PY'
from sqlalchemy import create_engine
from sqlalchemy.orm import Session

from school_routine_bot.db_files.db_models import Admin, User
from school_routine_bot.settings import get_settings

MESSENGER_ID = int("<ID_ПОЛЬЗОВАТЕЛЯ>")

settings = get_settings()
id_field = User.chat_id if settings.messenger_tag == "tg" else User.vk_id
engine = create_engine(settings.database)

with Session(engine) as session:
    user = (
        session.query(User)
        .filter(id_field == MESSENGER_ID)
        .one_or_none()
    )
    if user is None:
        raise SystemExit("Пользователь не найден. Проверьте ID и сервер.")

    # Оба бота при старте назначают админов по Telegram ID.
    if user.chat_id is not None and user.chat_id in settings.admins:
        raise SystemExit(
            "Сначала удалите Telegram ID из admins в .env "
            "и примените настройки через docker compose up."
        )

    admin = session.get(Admin, user.id)
    if admin is None:
        print("У пользователя уже нет роли главного администратора.")
    else:
        session.delete(admin)
        session.commit()
        print("Роль главного администратора снята. Пользователь сохранён.")

engine.dispose()
PY
```

Скрипт выбирает поле ID по настройке `messenger_tag` текущего контейнера. Для TG и VK его нужно выполнять отдельно на соответствующих серверах.

**Удалить только запись из базы недостаточно:** если Telegram ID останется в настройках, при следующем запуске бот снова выдаст роль. После выполнения скрипта дополнительный перезапуск не нужен — проверки прав читают базу. Роль дежурного по опозданиям и список получателей служебных уведомлений этот скрипт не меняет.

## Особенность ВКонтакте

В текущем развёртывании базы TG и VK раздельные. Список `admins` в `.env` обрабатывается по Telegram ID даже в VK-версии. Для пользователя только ВК назначение и отзыв прав выполняет разработчик в базе ВК; регистрация или смена прав на TG-сервере их не переносит.

## Сменить получателя служебных уведомлений (администраторы второго порядка - отвественные за пустые слоты и новых для тг-версии юзеров)

В `school_routine_bot/admin_base_1.json` замените запись нужного получателя, сохранив остальных. В шаблоне ниже замените `<ID_ПОЛУЧАТЕЛЯ>` на его числовой ID без кавычек и угловых скобок:

```text
[{"admin_id": <ID_ПОЛУЧАТЕЛЯ>, "name": "Иван", "by_father_name": "Иванович"}]
```

Укажите ID в соответствующем мессенджере и попросите получателя разрешить сообщения бота. Для теста без получателей используйте `[]`. В демо файл подключается к контейнеру с хоста; после изменения перезапустите сервис:

```bash
docker compose restart school-routine-bot
```

Это администраторы другого назначения - люди,в 13.00 получающие в ТГ-версии инфо о пустых слотах и о том, кто не является пользователем ТГ-бота. При передаче обязанностей проверьте и права администратора, и список получателей. Этот список не выдаёт права на команды `/admin` в ТГ / `admin` в ВК. Скрытая админская команда доступна только главному админу/админам и позволяет управлять списком дежурных по опозданиям.
