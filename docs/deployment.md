## Docker Compose

Все команды выполняются на нужном сервере из каталога проекта с `docker-compose.yaml`. Сервис один: `school-routine-bot`; мессенджер выбирается в `.env`. Для TG и VK используйте отдельные экземпляры и выполняйте команды для каждого сервера отдельно.

| Действие | Команда |
| --- | --- |
| Запуск / пересборка | `docker compose up -d --build school-routine-bot` |
| Обычный перезапуск | `docker compose restart school-routine-bot` |
| Применить изменения `.env` без сборки | `docker compose up -d --no-build school-routine-bot` |
| Остановка | `docker compose stop school-routine-bot` |
| Состояние | `docker compose ps -a` |
| Логи | `docker compose logs --tail 100 -f school-routine-bot` |

После запуска в выводе `docker compose ps -a` у сервиса `school-routine-bot` в колонке `STATUS` должно быть `Up` — контейнер запущен. Если строки нет или статус другой, проверьте логи.

После изменения `.env` команда `up -d --no-build` пересоздаёт контейнер с новыми настройками и запускает его в фоне. `--no-build` запрещает сборку образа; кеш сборки при этом не создаётся. [Описание `up`](https://docs.docker.com/reference/cli/docker/compose/up/).

Обычный [`restart`](https://docs.docker.com/reference/cli/docker/compose/restart/) не применяет новые переменные окружения. После изменения кода нужна пересборка образа. `school_routine_bot/admin_base_1.json` подключён с хоста: после его изменения достаточно перезапустить сервис.

`Ctrl+C` при просмотре логов завершает просмотр, а бот продолжает работать. Не запускайте параллельно того же бота через Poetry, systemd или второй контейнер.

## Обновление

Перед обновлением сохраните [резервную копию](database_backups.md). Если меняется схема базы, согласуйте с разработчиком порядок миграции: запуск бота не обновляет существующие столбцы автоматически. При ошибке команды не переходите к следующему шагу.

1. Подключитесь по SSH к нужному серверу. Замените `USER@HOST` на свои SSH-данные; по запросу введите пароль:
``` bash
ssh USER@HOST
```

2. Перейдите в папку проекта, заменив `/path/to/project` на свой путь:
``` bash
cd /path/to/project
```
3. Обновите согласованную ветку:
```bash
git pull
```
4. Запустите пересборку контейнера с проектом командой:
``` bash
docker compose build school-routine-bot
```
5. Когда пересборка завершится (чаще всего появляется текст built с галочкой),остановите предыдущий контейнер командой:

``` bash
docker compose stop school-routine-bot
```
Здесь ожидается даунтайм на время, пока Вы не приступите к следующему шагу!

6. Запустите новый контейнер.
```bash
docker compose up -d school-routine-bot
```
 Compose сам остановит старый контейнер и запустит новый; на это время бот будет недоступен. Ожидаемый статус — `Up`.

7. Если ничего не произошло в консоли, то все в порядке. Можете посмотреть логи  в реальном времени командой:
```bash
docker compose logs -f school-routine-bot
```
Проверьте отсутствие ошибок в логах и ответ бота, например кнопку «Ваши данные».

Рабочая база и JSON-файлы подключены с хоста, поэтому пересоздание контейнера их сохраняет. При откате нужны совместимые версия кода и база.

## Данные и логи

- На хосте сохраняются `data/` и `sent_reminders.json`; JSON-ключ и `school_routine_bot/admin_base_1.json` подключены только для чтения. Compose требует их наличия до запуска — подготовка описана в README.
- Основной способ диагностики — `docker compose logs`. Файл `/app/school_routine_bot.log` остаётся внутри контейнера и теряется при его пересоздании.
- Часовой пояс образа — `Europe/Moscow`. Проверка без запуска бота: `docker compose run --rm --no-deps --entrypoint date school-routine-bot '+%H:%M %z'`; ожидаемое смещение `+0300`.
- Расписание выгрузки опозданий указано в [руководстве пользователя](user_guide.md#выгрузка-в-таблицы), ночные копии — в [инструкции резервирования](database_backups.md).

Перед передачей логов удаляйте персональные данные и секреты. Общую базу двух процессов текущий код не защищает от повторной выгрузки; сохраняйте раздельную схему развёртывания.

## Проверка свободного места

Если обновлений и пересборок нет, проверяйте каждый сервер раз в месяц. Первую повторную проверку сделайте через неделю, чтобы оценить расход места. При быстром росте занятого места и перед пересборками проверяйте чаще.

После подключения по SSH выполните из любой папки:

```bash
df -h /
```

`Avail` — свободное место, `Use%` — доля занятого диска. Ориентир для проверки: **занято 80% и больше или свободно меньше 3 ГБ** — отправьте вывод разработчику для проверки и очистки.

Для диагностики разработчик может посмотреть объём данных Docker и системных журналов:

```bash
docker system df
journalctl --disk-usage
```

Эти команды ничего не удаляют. Кеш Docker накапливается при сборках образов; без пересборок место могут занимать растущие логи и резервные копии. Очистку выполняют по результатам проверки.
